# F1 — The verifiability funnel: repos are rarely opened, and you must make it one click deep

**Status:** Confirmed (qualified) · **Confidence:** moderate-high
**Sources:** 02, 05, 16, 17, 18, 19, 20 (industry + discussion; multi-method)

## Thesis
Most CV reviewers never open a repo — platform data (83% of GitHub users have zero commits/year; interview audits show code examined in ~2/50 interviews [17]) and funnel arithmetic (ATS filters ~75% of cold resumes; referrals are 30–50% of hires [20]) both point the same way. *But* the claim "GitHub has no value" is too strong: the hiring guide canon says code output works "at the top of the funnel" [02], the best 2025 survey names side projects/portfolios the #1 non-interview signal (38%) [19], and practitioners explicitly say "we checked the code there" — mostly for junior roles [05]. When reviewers do look, they skip green squares and stars and read a handful of merged PRs / specific files [05, 18].

## Implication for project choice
A project's CV value is *conditional on reachability*: link straight to the pinned repo, the specific PR, the specific file — "just have to show you where to look" [02], "linking them directly to specific files... makes the job much easier for the other side" [05]. A bare profile link burns the only chance you get.

## Evidence gaps
No academic/causal study of callback lift attributable to portfolio links exists in the corpus (explicitly hunted, not found [Channel A/D digests]). [19] measures *stated* influence, not verified behavior. [17]'s hard data is 2018-vintage.
