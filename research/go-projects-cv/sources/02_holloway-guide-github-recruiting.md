## Verbatim quotes
> "With an ever-growing number of engineers contributing to open source, GitHub profiles and GitHub contributions have become a potentially powerful complement (or even a partial replacement) to LinkedIn profiles." — main body, GitHub paragraph
> "Looking at someone's code output in the form of an open-source project or GitHub repo can work well at the top of the funnel, if the candidate has produced a large volume of code—effort on the candidate’s part is small (they just have to show you where to look), and signal is high." — main body, GitHub paragraph
> "(Later on, you may ask the candidate to dive deeper with you on one or two projects, as part of a past work sample interview.)" — parenthetical in the same GitHub paragraph
> "While GitHub stars and published code are powerful signals, it’s worth remembering that most engineers don’t have meaningful projects they can publish. A notable exception is students or other nontraditional candidates who deliberately publish projects on GitHub." — main body, GitHub paragraph
> "If an engineer has built a personal website or online resume it can be helpful to look at the site itself, both for links to projects and as a demonstration of frontend design or engineering, as appropriate." — main body, personal-website paragraph
> "The same principles for collecting signal from resumes apply to LinkedIn profiles, if the profiles are sufficiently filled in." — opening sentence

## Relevance
- Bears on hypotheses: H1 (hygiene/portability of signals), H3 (do reviewers actually open repos — and when), H4 (entry vs senior differences)
- Establishes the two-stage model of verifiability: GitHub/code output works "at the top of the funnel" as a cheap high-signal scan, then interviewers "dive deeper … on one or two projects" later — so a CV project must survive both a skim and a deep walkthrough (H3).
- Explicitly states published projects matter most for "students or other nontraditional candidates" — direct evidence for H4 that entry-level/self-taught CVs lean on project proof while experienced engineers are expected to have volume of professional code instead.
- Signals prized are volume of code, stars, and sustained contribution — engineering-output hygiene rather than domain novelty (H1); "just have to show you where to look" implies frictionless, findable presentation matters.
