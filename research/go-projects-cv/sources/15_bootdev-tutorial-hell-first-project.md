## Verbatim quotes
> "Tutorial hell is where you write code that others are explaining to you how to write, but you don't understand how to write it yourself when given a blank slate." — definition, opening section
> "At some point, it's time to take the training wheels off and build something *on your own*." — opening section
> "At Boot.dev, students write their first non-tutorial project after completing the following modules: Learn Python (course), Learn OOP (course), Build a Python CLI (project), Learn Algorithms (course), Learn Data Structures (course), Build a Maze Solver (project), **Personal Project 1** (when they build their first fully custom project)" — "When is it time to build your own project?"
> "I'm not saying you should watch 40 hours of video before building anything, but I *am* saying you should have a solid understanding of coding fundamentals before building your *own idea*. You should learn those fundamentals by *writing code*, but it's best if the projects and challenges you're working on are *guided* so that you can focus more on learning the *concepts* and less on figuring out what to build." — "When is it time to build your own project?"
> "The goal of this *first* project is simply to get you used to the process of building something from scratch. You just need to get some practice breaking down a project into smaller pieces." — "What's the goal of your first project?"
> "Try to spend 20-40 hours on this project." / "Commit your code to Git often, and push it up to GitHub." — "What are some good requirements for your first project?"
> "It's okay for (I'd even encourage) you to use third-party libraries! That said, make sure that some of the code that *you* write is doing something interesting. You don't want a razor-thin wrapper around a third-party library to be the only thing you've written." — "What are some good requirements for your first project?"
> "**Build something that you find interesting.** ... Even if the project you build is *simple* for now, at least it's *yours*." — "But what should I build?"
> "**You're going to get stuck.** If you don't get stuck, you probably chose an idea that's way too easy." — "You'll need help"
> "Don't have ChatGPT write your code for you! You won't learn that way" — "You'll need help"

## Relevance
- Bears on: learning axis + H4 (an explicit staged ORDER for project work: guided project → guided-with-constraints → first *personal* project, with sizing and difficulty calibration: 20-40 hours, deliberately "get stuck").
- The opposition/tutorial-hell channel: defines the failure mode (can't write code on a blank slate) and prescribes the fix — fundamentals learned through *guided* projects first, then one self-directed project; first personal project explicitly NOT for the resume ("probably isn't a project that will make its way onto your portfolio or resume").
- Practical CV-relevant requirements it attaches even to the first project: frequent Git commits, a real README, some genuinely interesting hand-written code (not a thin library wrapper) — i.e., signals reviewers look for are framed as learning artifacts, not decoration.
